## Phase 2.3: Embeddings Generation (13:40)

**Goal:** Add semantic search capability via local embeddings

**From Plan Section 2.3:**
- Model: all-MiniLM-L6-v2 (384 dimensions, local generation)
- Library: @xenova/transformers (browser-compatible transformers.js)
- Storage: sqlite-vss extension for vector similarity search

**Research Phase - Implementation Considerations:**

### Option 1: @xenova/transformers (Plan Recommendation)
**Pros:**
- ✅ Pure JavaScript (no Python dependencies)
- ✅ Works in Node.js and browsers
- ✅ Active maintainer (Xenova/transformers.js)
- ✅ ONNX runtime (fast inference)
- ✅ Model: all-MiniLM-L6-v2 supported

**Cons:**
- ⚠️ Large download (~50MB model files)
- ⚠️ First-run downloads models (startup delay)
- ⚠️ Memory footprint (~200MB loaded)

### Option 2: Native Python + subprocess
**Pros:**
- ✅ sentence-transformers is battle-tested
- ✅ Fast inference (native CPU/GPU)

**Cons:**
- ❌ Python dependency (breaks "npm install && go" workflow)
- ❌ Cross-platform complexity (Windows, macOS, Linux)
- ❌ Environment management nightmare

### Option 3: OpenAI/Anthropic API
**Pros:**
- ✅ Zero local computation
- ✅ State-of-art embeddings

**Cons:**
- ❌ **Privacy violation** (sends knowledge to 3rd party)
- ❌ API costs (per-token pricing)
- ❌ Requires internet (offline-incapable)
- ❌ Violates Core Philosophy #5 (Privacy-First)

### Decision: **Option 1 - @xenova/transformers** ✅

**Rationale:**
- Aligns with privacy-first architecture
- Pure JavaScript (no external dependencies)
- Offline-capable (models cached locally)
- Acceptable trade-off (50MB download vs privacy/offline)

**Implementation Strategy:**
1. Add @xenova/transformers dependency
2. Create EmbeddingGenerator class (lib/embeddings/generator.ts)
3. Lazy-load model (only when needed, cache after first use)
4. Event → text representation pipeline
5. Store embeddings in knowledge_events table
6. Add sqlite-vss for vector similarity search
